# AI KIDS — авторская образовательная платформа

Стартовый веб-проект публичной многопользовательской платформы AI KIDS: Next.js + Supabase + OpenAI API.

## Уже заложено
- Публичная главная страница и описание тарифов START / PRO.
- Регистрация и вход по email через Supabase Auth.
- Личный кабинет с историей сохранённых проектов.
- Мастерская: игры, сказки, иллюстрации (техническое задание), карточки, рабочие листы, КСП и авторские разработки.
- AI API endpoint с двуязычным режимом RU/KZ и возрастными настройками.
- Сохранение проектов в Supabase.
- Стартовый месячный лимит: 10 генераций для free, 300 для pro.

## Что нужно подключить владельцу проекта
1. Создать проект Supabase.
2. В Supabase SQL Editor выполнить `supabase/schema.sql`.
3. Скопировать `.env.example` в `.env.local` и заполнить ключи Supabase и OpenAI.
4. Установить Node.js 20+.
5. В папке проекта выполнить:
   ```bash
   npm install
   npm run dev
   ```
6. Открыть `http://localhost:3000`.

## Публикация в интернете
- Создать репозиторий GitHub и загрузить проект.
- Импортировать репозиторий в Vercel.
- Добавить те же переменные окружения в настройках Vercel.
- В Supabase Auth настроить Site URL и Redirect URLs на домен сайта.
- Подключить собственный домен в Vercel.

## Важные следующие этапы перед публичным запуском
- Подключить платёжный провайдер и серверную проверку подписок. Пока PRO — заготовка тарифа, переключение тарифа пользователем не реализовано.
- Перенести контроль квот в атомарную SQL-функцию, чтобы исключить параллельное превышение лимитов.
- Добавить проверку email, восстановление пароля, защиту от спама/rate limiting и CAPTCHA.
- Добавить юридические страницы: правила, политика конфиденциальности, согласие на обработку данных; определить оператора данных и требования юрисдикции запуска.
- Настроить мониторинг, резервное копирование, обработку жалоб и модерацию пользовательского контента.
- Генерация картинок и экспорт в PDF/DOCX пока не подключены; сейчас для иллюстраций создаётся текстовое ТЗ.
- Добавить админ-панель с отдельной серверной ролью; не выдавать обычному пользователю административные права.

## Безопасность
- Никогда не помещать `OPENAI_API_KEY` и `SUPABASE_SERVICE_ROLE_KEY` в клиентский код.
- Не коммитить `.env.local`.
- Перед реальным приёмом платежей провести проверку безопасности и юридических документов.
